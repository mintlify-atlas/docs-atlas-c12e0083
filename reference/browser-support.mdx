## Overview

Requiem for Earth uses modern CSS features including animations, custom properties, and viewport units. This page documents browser compatibility and provides testing recommendations.

## Core CSS Features

### CSS Custom Properties (CSS Variables)

<ParamField path="CSS Custom Properties" type="feature">
  Support for `var()` and custom properties
  
  **Used for:** Color theming (`--primary`, `--secondary`, `--tertiary`)
  
  **Browser Support:**
  - Chrome: 49+ ✓
  - Firefox: 31+ ✓
  - Safari: 9.1+ ✓
  - Edge: 15+ ✓
  - Opera: 36+ ✓
  - iOS Safari: 9.3+ ✓
  - Chrome Android: 49+ ✓
  
  **IE Support:** Not supported in IE 11 or below ✗
  
  **Fallback Strategy:**
  ```css
  /* Provide fallback for IE */
  .footer {
    background-color: #56877d; /* Fallback */
    background-color: var(--tertiary); /* Modern browsers */
  }
  ```
</ParamField>

### CSS Animations and Keyframes

<ParamField path="CSS Animations" type="feature">
  Support for `@keyframes` and animation properties
  
  **Used for:** All page animations (7 keyframe sequences)
  
  **Browser Support:**
  - Chrome: 43+ ✓ (4+ with -webkit- prefix)
  - Firefox: 16+ ✓ (5+ with -moz- prefix)
  - Safari: 9+ ✓ (4+ with -webkit- prefix)
  - Edge: 12+ ✓
  - Opera: 30+ ✓ (12+ with -webkit- prefix)
  - iOS Safari: 9+ ✓ (3.2+ with -webkit- prefix)
  - Chrome Android: 43+ ✓
  
  **Prefixed Support:** -webkit- prefix extends support to older mobile browsers
  
  **Animation Features Used:**
  - `animation-name`
  - `animation-duration`
  - `animation-delay`
  - `animation-timing-function` (ease, ease-in, ease-out, ease-in-out)
  - `animation-fill-mode: forwards`
</ParamField>

### Transform Properties

<ParamField path="CSS Transforms" type="feature">

  **Used for:** Logo positioning and scaling animations
  
  **Browser Support:**
  - Chrome: 36+ ✓
  - Firefox: 16+ ✓
  - Safari: 9+ ✓
  - Edge: 12+ ✓
  - Opera: 23+ ✓
  - iOS Safari: 9+ ✓
  - Chrome Android: 36+ ✓

## Polyfills and Fallbacks

### For Internet Explorer Support

If IE11 support is required, implement these strategies:

```css
/* 1. CSS Custom Properties Fallback */
:root {
  --primary: #93a87e;
  --secondary: #bade57;
  --tertiary: #56877d;
}

.footer {
  background-color: #56877d; /* IE fallback */
  background-color: var(--tertiary); /* Modern browsers */
}

/* 2. Use PostCSS with cssnext for automatic fallbacks */
/* Or use css-vars-ponyfill JavaScript library */
```

### For Older Safari/iOS

```css
/* Add -webkit- prefixes for broader mobile support */
.cbtlogo {
  -webkit-animation: cbt-an1 3s 2s forwards ease;
  animation: cbt-an1 3s 2s forwards ease;
}

@-webkit-keyframes cbt-an1 {
  /* keyframe rules */
}
```

## Testing Recommendations

### Desktop Testing

<Steps>
  <Step title="Test on Major Browsers">
    Verify animations and layout on:
    - Chrome (latest)
    - Firefox (latest)
    - Safari (latest, macOS only)
    - Edge (latest)
  </Step>
  
  <Step title="Test Responsive Breakpoints">
    Use browser DevTools to test:
    - Desktop (1920px, 1440px, 1024px)
    - Tablet landscape (1024px)
    - Tablet portrait (768px)
    - Mobile (375px, 414px)
  </Step>
  
  <Step title="Test Animation Performance">
    - Open DevTools Performance panel
    - Record page load and animation sequence
    - Check for dropped frames
    - Verify smooth 60fps playback
  </Step>
</Steps>

## Known Issues and Limitations

### Internet Explorer 11
- ✗ CSS Custom Properties not supported
- ✗ `min()` function not supported
- ⚠ Animations work but may need prefixes
- ⚠ Viewport units have some bugs

### Safari < 11.1
- ✗ `min()` function not supported
- ⚠ May need `-webkit-` prefixes for animations

### Mobile Considerations
- Viewport height (`vh`) can behave unexpectedly with browser chrome
- Consider using `dvh` (dynamic viewport height) for modern browsers
- Test animation performance on lower-end devices
